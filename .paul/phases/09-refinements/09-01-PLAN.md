# Plan 09-01: Mobile Numberpad

## What
A toggleable on-screen numberpad for mobile users. When active, prevents the native mobile keyboard from opening (which zooms the viewport and obscures the drill question). Provides digit/letter/control keys via a panel beneath the drill card.

## Why
On mobile, tapping a `.drill-input` (font-size 10px) causes iOS Safari to zoom and open the native keyboard, pushing the question out of view. A custom numberpad with `inputmode="none"` on inputs eliminates both the keyboard and the zoom.

## Files Affected
- `utils/numpad.js` *(new)*
- `index.html`
- `style.css`

## What Was Done

### `utils/numpad.js` (new)
`window.BitPitch.Numpad` IIFE module:
- `init()` — sets up MutationObserver on `#drill-area` (childList); tracks `_activeInput` via focusin delegation
- `toggle()` — flips `_on`, blurs active input (closes native keyboard), sets/removes `inputmode="none"` on `.drill-input` elements, shows/hides `#numpad-panel`, toggles `.numpad-mode` on `<body>`
- `onDrillEnd()` — hides panel, clears `_activeInput`; preserves `_on` state across drills
- `_onDomChange()` — deferred MutationObserver callback; re-injects toggle button when drill-card is rebuilt; calls `_syncPanel()` to hide panel during feedback phase
- `_syncPanel()` — hides panel when `#next-btn` or `.feedback-box` present; shows panel otherwise
- `_injectToggle(card)` — appends `#numpad-toggle` button to `.drill-card` with `position: absolute; bottom: 0; right: 0`
- `pressKey(key)` — handles all numpad key presses including backspace, cursor left/right, tab (focus next input), enter (dispatches KeyboardEvent to document)

### `index.html`
- Added `#numpad-panel` div inside `.drill-body` after `#drill-area`: 19 keys in a 5-column CSS grid (rows: 789,./  456KM  123←→  0 DEL TAB ENT×2)
- All `.np-btn` buttons use `onmousedown="return false"` to prevent focus-steal
- Added `<script src="utils/numpad.js">` before exercise scripts

### `style.css`
- `#numpad-toggle`: `position: absolute; bottom: 0; right: 0` within `.drill-card`; purple border/text when inactive; blue fill when active
- `#numpad-panel`: CSS grid 5 columns; blue border, no top border (connects to card)
- `.np-btn` / `.np-wide`: numpad key styles; active flash blue
- `.numpad-mode .drill-input { font-size: 16px !important }` — iOS zoom prevention

### `app.js`
- `AppState.goHome` — calls `BitPitch.Numpad.onDrillEnd()` before `renderHome()`
- `AppState.showSummary` — calls `BitPitch.Numpad.onDrillEnd()` before `showScreen('summary')`
- Boot — calls `BitPitch.Numpad.init()` after `renderHome()`

### Change 2: ENT key directly submits
**Request:** ENT on the numpad should act as a submit button — find and click the submit button directly, not just dispatch a keyboard Enter event to document.

**Current behavior:** ENT dispatches `new KeyboardEvent('keydown', { key: 'Enter', bubbles: true })` to `document`, which exercises handle via their `document.onkeydown` handlers — but those only fire during the feedback phase (Enter-to-NEXT), not during the question phase.

**Fix in `numpad.js` `pressKey('enter')`:**
```javascript
case 'enter': {
  // Try to click the submit button directly
  var submitBtn =
    document.getElementById('submit-btn') ||
    document.getElementById('submit-all-btn') ||
    document.querySelector('#drill-area .btn-primary:not([disabled])');
  if (submitBtn && !submitBtn.disabled) {
    submitBtn.click();
  } else {
    // Fallback: dispatch Enter (handles Enter-to-NEXT in feedback phase)
    var evt = new KeyboardEvent('keydown', { key: 'Enter', bubbles: true, cancelable: true });
    document.dispatchEvent(evt);
  }
  return;
}
```

## Notes
- The MutationObserver approach (re-injecting the button) works because exercises use `innerHTML =` and `innerHTML +=` which rebuild the DOM. `childList` (no `subtree`) avoids triggering on timer text updates.
- `onmousedown="return false"` on numpad buttons prevents focus steal so `_activeInput` remains valid.
- `_on` state persists across drills — mobile users don't re-enable numpad each time.

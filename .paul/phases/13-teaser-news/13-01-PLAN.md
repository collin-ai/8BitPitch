<objective>
## Goal
Build the teaser screen — shown once between the splash animation and the log-in entry screen. It presents a Value Equity Ask triangle question (ex04-style). The player holds the correct answer for 3 seconds to advance. This also acts as a lightweight anti-bot gate.

## Purpose
Phase 10-04 builds the splash → log-in entry flow. This plan inserts a teaser between them: an interactive moment that reinforces the app's identity (deal math) before the player even reaches the log-in screen. The hold-to-confirm mechanic distinguishes a human from an automated browser.

## Output
- `#screen-teaser` screen in index.html
- Teaser layout: Value Equity Ask triangle with one blank + three answer buttons
- Hold-to-confirm mechanic (3 seconds on the correct answer → correct sound → advance)
- CSS for screen layout and hold-progress indicator
- `runTeaser()` in app.js inserted into startup flow after splash
</objective>

Given the teaser screen is showing

Then the correct sound plays (Sound.playCorrect()) and the app advances to the log-in entry screen

## AC-4: Release Before 3 Seconds → Reset
Given the player is holding an answer button
When they release before 3 seconds

<task type="auto">
  <name>Implement runTeaser() — question generation, hold mechanic, startup flow integration</name>
  <files>app.js</files>
  <action>
    **Question generation** using existing `window.BitPitch.randTriangle()` from utils/random.js:
    - Call randTriangle() to get { valuation, equity, ask }
    - Randomly pick one of the three as the blank (the "answer")
    - Generate two wrong answers: ±15–25% of the correct value (rounded to nearest round number)
    - Shuffle the three choices

    **runTeaser() function in app.js:**
    ```
    var _teaserFailCount = 0;
    var _teaserCorrectIndex = null;
    var _holdTimer = null;

    AppState.runTeaser = function() {
      _teaserFailCount = 0;
      var q = generateTeaserQuestion();   // uses randTriangle
      renderTeaserTriangle(q);            // populates #teaser-triangle
      renderTeaserChoices(q);             // populates #teaser-choices with 3 buttons
      showScreen('teaser');
    };
    ```

    **Hold mechanic** (on each `.teaser-choice-btn`):
    - onmousedown / ontouchstart: start a 3000ms setTimeout; add `.holding` class for CSS animation
    - onmouseup / ontouchend / onmouseleave: clearTimeout; remove `.holding` class
    - On timer fire (3s elapsed):
      - If correct button: Sound.playCorrect() + vibrate; AppState.advanceFromTeaser()
      - If wrong button: add `.rejected` class for 300ms; increment _teaserFailCount;
          if _teaserFailCount >= 3: show #teaser-skip

    **AppState.advanceFromTeaser():**
      clearTimeout(_holdTimer);
      showScreen('login-entry');

    **Startup flow** — update runSplash() (created in Phase 10-04):
      After splash fade-out, call AppState.runTeaser() instead of showScreen('login-entry').
      AppState.advanceFromTeaser() then calls showScreen('login-entry').

    Use passive event listeners for touch events to avoid scroll-blocking warnings.
    Do not modify randTriangle() in utils/random.js — use it as-is.
  </action>

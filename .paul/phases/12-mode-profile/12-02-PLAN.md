<objective>
## Goal
Build a reusable 108px profile widget component. Left third: an 8-bit CSS box-shadow sprite character and the user's username below it. Right two-thirds: a swipeable stats panel showing XP total on the first slide and per-exercise level on the second slide.

## Purpose
The profile widget is a compact identity + progress summary that will appear in two places: at the top of the Profile & Settings screen (Phase 12-03) and in the main menu above the drill grid (Phase 13-02). Building it as a standalone, reusable component here prevents duplication.

## Output
- `.profile-widget` HTML structure defined in a JS render function (`renderProfileWidget(containerId)`)
- 8-bit CSS box-shadow character (no images, no external fonts)
- Swipeable right panel: slide 0 = total XP; slide 1 = level per exercise
- Widget reads from `AppState.currentUser` and `window.BitPitch.Levels` (Phase 12-04)
- Widget CSS in style.css
- Guest state: character shown, username replaced with "GUEST", stats show sign-in prompt
</objective>

<task type="auto">
  <name>Implement renderProfileWidget() in app.js</name>
  <files>app.js</files>
  <action>
    Add `AppState.renderProfileWidget` function. It accepts a container element ID string,
    clears the container, builds the widget DOM, and inserts it.

    **8-bit sprite** — a single `.pw-sprite` div with a hardcoded `box-shadow` string
    representing a ~12×16 pixel humanoid figure. Each shadow entry: `Xpx Ypx 0 0 COLOR`.
    Use `var(--fg)` (white) for body pixels and `var(--accent)` (yellow) for head pixels.
    The pixel unit is 3px × 3px (adjust sprite shadow offsets accordingly).
    Keep the sprite simple: head (3×3 block), body (3×5), arms (1×3 each side), legs (1×3 each).
    Write the full box-shadow list inline in the JS string — do not use a separate CSS class for sprite pixels.

    **Widget structure (built via JS DOM or innerHTML):**
    ```
    .profile-widget
      .pw-left
        .pw-sprite          ← box-shadow pixel art
        .pw-username        ← username or "GUEST"
      .pw-right             ← click/swipe target
        .pw-slides          ← translated by JS
          .pw-slide#0       ← XP total (or guest prompt)
          .pw-slide#1       ← level per exercise
        .pw-pip-row
          .pw-pip × 2       ← slide indicators
    ```

    **Slide 0 content (logged-in):**
    ```
    <div class="pw-slide-label">TOTAL XP</div>
    <div class="pw-xp-value">{totalXP}</div>
    <div class="pw-xp-unit">XP</div>
    ```

    **Slide 1 content (logged-in):**
    8 rows, one per exercise:
    ```
    <div class="pw-level-row">
      <span>{shortName}</span>
      <span class="pw-level-val">LV {level}</span>
    </div>
    ```
    Short names (7 chars max): PERC SN / RoT MUL / DBL TRP / VAL TRI / GRWTH R / BRK EVN / TAM EST / TRIATH

    **Guest state (slides replaced):**
    Slide 0 only, content:
    ```
    <div class="pw-guest-prompt">SIGN IN TO<br>TRACK XP</div>
    ```
    Pip row hidden.

    **Swipe/click logic:**
    - Track `_pwSlide = 0` (local var inside the widget render scope)
    - `.pw-right` onclick: advance slide (wrap: 0→1→0)
    - Touch: ontouchstart records startX; ontouchend: if deltaX < -30, advance; if deltaX > 30, retreat
    - To advance: `_pwSlide = (_pwSlide + 1) % 2`; update `.pw-slides` transform and pip classes
    - Use `transform: translateX(-{_pwSlide * 100}%)` on `.pw-slides`

    **Data source:**
    - `AppState.currentUser` for username (strip `@bitpitch.local`)
    - `window.BitPitch.Levels.getTotalXP()` for total XP
    - `window.BitPitch.Levels.getLevelForExercise(exId)` for each of ex01–ex08

    Wrap Levels calls in a guard: if `window.BitPitch.Levels` is undefined, show XP as `—`.

    Do not modify any other part of app.js.
  </action>

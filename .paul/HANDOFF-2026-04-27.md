## Key Changes Made This Session (vs Prior Handoff)

### 11-04 — Ads System (amended)
**Old:** Ad shown after MENU button on summary screen.
**New:** Ad plays BEFORE the score screen — inserted at exercise completion via `maybeShowAd(proceedFn)`. The `proceedFn` is `showSummary()`; it's stored as `AppState._adProceedFn` and called by `continueFromAd()`. MENU on summary still goes directly to home — no ad there.

### 11-05 — Extended Sound System (new)
Four sounds added to `utils/sounds.js`:
- `playClick()` — 40ms square-wave tick; wired via single event delegation listener on `document` for all `.btn` elements
- `playSplash()` — 4 ascending tones (A3→C#4→E4→A4) at 350ms intervals; fires at start of `runSplash()`
- `playSessionComplete()` — two-beat chord flourish; fires when summary screen appears (after ad)
- `playLevelUp()` — ascending run + held chord; fires 700ms after session complete when level threshold crossed in `recordCorrect()`

### 12-05 — Local Leaderboard & Upload (new)
- `bp_local_sessions` localStorage key — JSON array, capped at 40 session objects
- `saveLocalSession()` called from `showSummary()` for ALL users (guest and logged-in)
- `#screen-local-leaderboard`: shows session count + "X OF 40 SLOTS USED — Y REMAINING" + UPLOAD SCORES button
- Upload → `_showAd()` directly (bypasses the exercise-counter gate) → after CONTINUE → sessions cleared, history rendered in Profile & Settings
- `bp_uploaded_sessions` persists uploaded history across refreshes
- Cap notice on summary screen when full
- Screen header back button says "PROFILE & SETTINGS" (not MENU)

### 12-06 — Settings Screen (new, moved from 13-04)
Sections: ACCOUNT (sign in/out/register), AUDIO & INPUT (sound, vibration, numpad default), GAMEPLAY (default difficulty selector), DATA (clear local data with confirm modal), ABOUT (app info).
SETTINGS button in Profile screen below the Profile Widget, above the score table.
